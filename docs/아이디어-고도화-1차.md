# 화면 필기·스마트 캡처 통합 앱 — 아이디어 고도화 1차

2026-11-24 · 딥서칭: Antigravity(Gemini Pro Orchestrator Neon) · 아이디어: Codex(GPT-6.2 Astra High) · 최종 검수·통합: Claude(Opus 5.5) · 상태: **PRD 전 아이디어 단계**

## 0. 결론 요약

- **제품 한 줄**: 아이캔 줌잇(확대·판서·타이머) + Snipaste(스마트 캡처·핀) + 교실 위젯(Classroomscreen)을 **오프라인 한 앱**으로. 지금 있는 앱은 모두 한쪽 기능만 하거나 한쪽 OS만 지원한다.
- **핵심 장면**: 교재에서 문제 한 칸을 스마트 캡처 → 화면에 핀 → 답 가리기 → 확대·판서로 풀이 → 답 공개 → 타이머. 처음 쓰는 교사가 30초 안에 끝낼 수 있어야 한다.
- **가장 큰 빈칸**: ① 판서를 유지한 채 스크롤·클릭(아이캔 줌잇 실사용자 질문) ② 무료 오프라인 한글 OCR·QR 해독 ③ 학교 PC(관리자 권한 없음·SmartScreen·Store 차단)에서 바로 실행 ④ Windows·macOS 동시 지원.
- **플랫폼 추천**: **Tauri 2(Rust) + Svelte 5**(Tidy-Task-Local과 같은 구성). 캡처·영역 인식·확대·OCR은 Rust와 OS 네이티브 API, 위젯·설정·명령 팔레트는 웹 UI. 필기 엔진은 웹 Canvas로 시작해 지연을 재고, 모자라면 네이티브(D3D/Metal)로 바꾼다.
- **무료 배포**: Windows는 MS Store(MSIX — 개인 등록·서명 모두 무료)가 주 경로, GitHub 포터블 ZIP은 보조(무서명이면 SmartScreen 경고). macOS는 공증(연 $99) 전까지 고정 자체 서명 + "그래도 열기" 안내로 시작.

### 영상에서 확인한 실제 사용 장면

- **아이캔 줌잇(이지쌤교실 영상)**: 카페에서 ZIP을 받아 실행하면 "Windows의 PC 보호" 경고가 떠서 '추가 정보 → 실행'으로 넘긴다. 영상 속 교사는 기본 Ctrl+1~4 대신 **F1~F4 한 키**로 바꿔 쓴다. 댓글 질문: *"스크롤하려면 ESC로 나가야 하는데 그러면 판서가 다 지워진다. 판서를 유지하며 스크롤할 방법이 있나요?"*
- **Snipaste(공부해서 남주는 선생님 영상)**: 패들렛 QR을 캡처해 핀으로 띄워 두고 "QR 다시 보여 주세요"에 바로 대응, **쿨메신저 공지**를 캡처해 메모처럼 고정, 학생 이름은 모자이크한 뒤 한글(HWP)에 붙여 넣기, 단축키 충돌 때문에 F8·F9로 바꿈.

## 2. 기회 — 사용자 불만 상위 10

1. 판서를 유지한 채 스크롤·클릭을 할 수 없다(아이캔 줌잇).
2. 스크롤(긴 화면) 캡처가 없다(Snipaste 최다 요청).
3. 무료 오프라인 한글 OCR·QR 해독이 없거나 유료다.
4. 필기·캡처·핀·타이머에 앱 3~4개를 띄우고 단축키가 서로 부딪힌다.
5. Windows·macOS 중 한쪽만 지원한다.
6. 학교 PC 제약: 관리자 권한 없음, Store 차단, SmartScreen·백신 오탐.
7. 교탁 FHD + 4K 전자칠판처럼 배율이 섞이면 좌표가 밀린다.
8. 구독·광고 피로(Epic Pen, 알캡처, CleanShot X).
9. 캡처에 그린 주석을 나중에 고칠 수 없고 바탕화면에 파일이 쌓인다.
10. 웹 교실 위젯은 오프라인·방화벽에 약하고 다른 앱 위에 못 띄운다.

## 3. 제품 콘셉트

### 원칙 5가지

- 수업 흐름을 끊지 않는다 — 원래 앱을 그대로 두고, 한 번에 원래 화면으로 돌아간다.
- 오프라인·무설치 가능·무광고·외부 전송 없음·계정 없음.
- 한 키, 한 툴바 — 모든 기능이 같은 단축키 체계와 같은 툴바를 쓴다.
- 학생 개인정보는 기본으로 보호한다.
- Windows와 macOS에서 같은 경험을 준다.

### 핵심 흐름(MVP 판정 기준)

1. 영역 캡처 → 창·UI 요소 자동 인식, 휠로 범위 조절
2. 화면에 붙이기(핀) → 답 덮기(되돌릴 수 있음)
3. 핀 위·화면 위 확대와 판서
4. 핀 옆에 타이머 붙이기
5. 답 공개 → 필요한 것만 보관함에 담기

### 모드 구조

- **판서 3단**: 정지 판서(줌잇식) / 라이브 판서(클릭 통과 전환, 판서 보존) / 칠판(화이트·블랙·모눈·원고지 등)
- **캡처·핀**: 스마트 캡처, 핀, 가리기, OCR·QR
- **위젯**: 타이머·뽑기·신호등 등을 항상 위 작은 창으로
- **명령 팔레트**: 모든 유틸리티를 이름으로 검색해 실행(유틸리티 아카이브의 입구)

## 5. 스마트 로직 아이디어

- **영역 인식 3단**: 창(Windows DWM · macOS SCWindow) → UI 요소(Windows UI Automation `ElementFromPoint` · macOS `AXUIElementCopyElementAtPosition`) → 콘텐츠 경계(정지 프레임의 여백·윤곽선 분석). 요소 정보가 없거나 느리면 즉시 창·드래그로 넘어간다.
- **캡처 내용 판별 → 다음 행동 하나만 추천**: 글자 → 텍스트 복사, QR → 내용 보기, URL → QR로 띄우기, 단색 → HEX 복사, 표 → 표로 복사. 추천은 툴바 마지막 칸 하나에만 두어 버튼 위치가 흔들리지 않게 한다.
- **판서 보정**: One Euro Filter로 떨림 보정(빠른 획은 지연 최소, 느린 획은 흔들림 감소). 획 끝을 잠깐 누르면 직선·원·사각형 후보를 보여 준다. 작은 한글 획과 점은 보존. 강도 끔/약/강.
- **스크롤 따라가는 판서**(제안 · 난이도 상): 판서 레이어를 화면이 아니라 문서에 붙인다. UI Automation ScrollPattern·macOS 접근성 스크롤 값을 읽고, 안 되면 연속 프레임의 이동량을 추정해 판서를 함께 움직인다. 아이캔 줌잇 사용자 질문에 대한 직접적인 답.
- **발표 상황 감지**: PPT 슬라이드 쇼·전체 화면 브라우저를 감지하면 "발표 도구 띄우기"를 한 번만 제안. 앱별로 "다시 묻지 않기".
- **다중 모니터**: 모니터별 배율·회전·좌표 분리(Per-Monitor DPI V2 · NSScreen/SCDisplay). TV 연결이 끊기면 핀을 남은 화면으로 회수.
- **학생용 화면 분리**(P1): 확장 모드에서 TV에는 교사가 승인한 핀·판서만, 교사 화면에는 원본과 도구.

## 6. 단축키·UX

- **첫 실행 프리셋 선택** — 옮겨 오는 사용자가 새로 외울 것이 없게 한다.
   - ① 아이캔 줌잇식: Ctrl+1 확대 · Ctrl+2 판서 · Ctrl+3 타이머 · Ctrl+4 실시간 확대
   - ② Snipaste식: F1 캡처 · F3 핀
   - ③ 한 손 F키식: F1~F4 (영상 속 교사 사용법)
   - ④ 충돌 적은 추천안: 리더 키(Ctrl+Shift+1) → 숫자로 도구 선택, 전역 키는 3개 이하
- **모드 안 단축키는 줌잇 체계 계승**: P·M·T·S·D·E, 색 R·Y·G·O·B·L, 화이트/블랙보드, 휠 = 확대, Ctrl+휠 = 굵기, Shift+휠 = 배경 밝기, Space = 가운데, Esc = 나가기(판서는 보존).
- **리더 키**: 누르면 화면에 명령 팔레트와 다음 키 안내가 뜨고, 숫자나 한글 명령명으로 고른다.
- **충돌 처리**: OS 등록이 실패하면 그 자리에서 알리고 다른 조합을 제안. 한/영·오른쪽 Alt·Ctrl+Space·Caps Lock, macOS 캡처(⌘⇧3/4/5)·Spotlight(⌘Space)는 추천에서 뺀다. 한글 조합 중 Enter가 핀 생성으로 이어지지 않게 분리.
- **macOS**: F키는 기본이 밝기·소리 키라 Fn이 필요 → 맥 기본 프리셋은 Control·Option 조합.
- **펜·전자칠판**: 펜 측면 버튼 = 누르는 동안 지우개, 툴바는 좌·우·하단 도킹, 터치 목표 48px 이상, 길게 눌러 원형 메뉴.
- **설정 화면**: 표 한 장(동작 | 현재 키 | 전역/모드 안 | 바꾸기). 칸을 누르고 원하는 키를 누르면 등록(줌잇 방식), "지금 시험" 버튼.
- **툴바**: 기본은 단순(펜·형광펜·지우개·확대·캡처·타이머) + 접이식 고급 패널. 선택 직후에는 복사·핀·가리기 버튼을 같은 자리에 고정.

### 구조에 대한 검수 의견

- **창을 역할별로 나눈다**: 판서 창(모니터별) · 툴바 창 · 핀 창(핀마다) · 위젯 창. Tauri의 클릭 통과는 창 전체 단위라서, 한 창 안에 "일부만 통과"를 만들려 하지 않는다.
- **필기 엔진은 측정으로 결정**: ① 웹 Canvas(저지연 캔버스, 합쳐진·예측 포인터 이벤트)로 시작 — 정지 판서는 배경이 멈춰 있어 충분할 가능성이 크다. ② 펜 → 잉크 표시 지연이 p95 50ms를 넘으면 네이티브 렌더러(D3D/Metal)로 교체. (Codex는 처음부터 네이티브, Antigravity는 Rust + Canvas를 권해 측정으로 가르기로 정리.)
- 핀이 10개 이상일 때 메모리를 재고, 필요하면 핀만 네이티브 창으로 바꾼다.
- **코드 참고**: PowerToys ZoomIt(MIT), gInk·ppInk(MIT), xland/ScreenCapture(MIT), xcap(Apache-2.0), RapidOCR(Apache-2.0). ShareX·Flameshot·ksnip·OpenBoard(GPL)는 기능·UX만 참고하고 코드는 가져오지 않는다.
- **첫 기술 시제품 순서**: 투명 판서 창 + 클릭 통과 전환 → 정지 확대 → UI 요소 인식 캡처 → 핀 10개 → 한글 OCR. 각 단계를 Windows·Mac 실기기에서 잰다.

## 10. 위험·함정

- macOS Sequoia는 화면 기록 앱에 주기적(월 단위) 재허용 알림을 띄우고, 공식 영구 해제 방법이 없다. 손쉬운 사용 권한은 요소 인식을 켤 때만 요청한다.
- 자기 창이 캡처에 찍히는 문제: 캡처할 때 자체 창 제외(SCContentFilter / `WDA_EXCLUDEFROMCAPTURE`). DRM·보호 화면은 "이 화면은 가져올 수 없어요"로 안내.
- 배율이 섞인 다중 모니터, 회전, 음수 좌표, 모니터 탈착.
- 학교 보안 프로그램·백신 오탐, Store 차단, WebView2가 없는 구형 PC(LTSC) → 런타임 포함판 검토.
- 학생 정보 재노출: 가린 이미지는 픽셀 합성본만 클립보드·저장·썸네일로 내보낸다.
- 성능 목표 [추정]: 펜 → 잉크 p95 50ms 이하, 1080p 실시간 확대 30fps 이상, 핀 10개 메모리 측정.
- 상표·외형: '아이캔' 'Snipaste' 'ZoomIt'의 이름·아이콘·화면 모양은 쓰지 않는다. 기능은 참고하되 이름과 디자인은 독자적으로.

## 13. 1차 프로토타입 구현 목표 (2026-11-24 결정 반영)

> 2026-11-25: 이 절은 [PRD.md](PRD.md) v0.2가 이어받았다(벤치마크 실측 반영, 요구사항 ID·합격 기준 추가). 아래는 v0.1 기록으로 남긴다.

**결정 사항**: 1차 사용자 = **발표자** · 기능은 핵심만 · 플로팅 툴바 없음(트레이 아이콘 → 설정 창) · 듀얼 모니터 필수 · DB·로그인·서버 없음 · 디자인은 Tidy-Task-Local을 계승해 아기자기하고 깔끔하게 · 플랫폼은 Tauri 2 추천안 확정.

### 13.1 동작 원칙

- 실행하면 끝. 화면에는 아무것도 뜨지 않고 트레이(맥은 메뉴 막대) 아이콘만 상주한다.
- 모든 기능은 단축키로 시작하고, **커서가 있는 모니터**에서 뜬다. 범위 캡처(F1)만 모든 모니터를 한꺼번에 덮는다.
- 트레이 아이콘 클릭 → 설정 창. 트레이 메뉴: 설정 · 저장 폴더 열기 · 단축키 잠시 끄기 · 종료.
- 화면 위 안내는 최소한으로: 모드에 들어갈 때 1초 정도 떴다 사라지는 작은 말풍선("판서 · 빨강 · 펜"), 커서 모양으로 현재 도구·색 표시, **?** 키를 누르면 단축키 한 장 안내.
- 설정은 로컬 파일 하나(tauri-plugin-store). 통계·계정·외부 전송 없음.

### 13.2 기능 목표와 난이도

| 기능 | 완료 기준 | Windows | macOS |

| **F1 범위 캡처**<br>(스마트 인식) | 누르는 순간 모든 모니터를 정지 화면으로 덮는다. 커서 아래 창·UI 요소를 자동으로 강조 → 클릭하면 그 영역, 드래그하면 직접 범위. Tab = 창↔요소 전환, 휠 = 범위 넓히기/좁히기, 방향키 = 1px 조정, 크기 배지·확대경 표시. ### 13.4 전역 단축키 기본값과 주의점

| 동작 | Windows | macOS 제안 |
|---|---|---|
| 범위 캡처 / 창 캡처 / 녹화 | F1 / F2 / F3 | F1 / F2 / F3 (맥 키보드는 Fn과 함께, 또는 "표준 기능 키" 설정) |
| 판서 / 화면 확대 / 칠판 | Alt+1 / Alt+2 / Alt+3 | ⌥1 / ⌥2 / ⌥3 (같은 자리의 키) |

- **F키를 전역으로 잡으면 다른 앱의 F1(도움말)·F2(파일 이름 바꾸기·엑셀 셀 편집)·F3(찾기)이 이 앱이 켜져 있는 동안 막힌다.** 발표자에게 F2 손실은 체감이 크다. 기본값은 요청대로 두되, 첫 실행 안내에 이 사실을 한 줄로 알리고 설정에서 바로 바꿀 수 있게 한다. (Snipaste도 F1·F3을 쓰고 사용자가 받아들인 전례가 있다.)
- 맥의 ⌥+숫자는 원래 특수문자(¡™£) 입력이라 이 앱이 켜져 있으면 그 입력이 막힌다. 영향은 작지만 안내한다.
- 등록 실패(다른 앱이 먼저 쓰는 경우)는 설정 창 해당 줄에 바로 표시하고 다른 조합을 고르게 한다.

### 13.5 디자인 방향 (Tidy-Task-Local 계승)

- 같은 기술: Tauri 2.10 · **Svelte 5** · Tailwind 4 · bits-ui · lucide 아이콘. (1차 문서의 React 제안을 Tidy와 맞춰 Svelte로 바꾼다 — 설정 창 부품과 테마를 그대로 가져올 수 있다.)
- 설정 창: Tidy의 SettingsPanel(둥근 카드 17px · 아이콘 말풍선 · 굵은 제목) · SwitchRow · 테마 견본 구조. 색은 Tidy 15종 파스텔 테마 토큰 중 몇 개로 시작.
- 화면 위 요소: 둥근 알약 모양 말풍선, 파스텔 강조색, 부드러운 등장·사라짐(0.15초 안팎). 캡처 선택 테두리·크기 배지·확대경도 같은 톤.
- 트레이 아이콘: 귀여운 전용 아이콘, 녹화 중 빨간 점, 단축키 꺼짐 상태는 흐리게.
- 효과음(찰칵·녹화 시작음)은 설정에서 켜고 끔.

### 13.6 기술 구조 (프로토타입)

- **창 구성**: 모니터마다 투명 오버레이 창 1개(평소 숨김, 모드에 들어갈 때 표시) + 설정 창 1개 + 말풍선 창. 오버레이 창은 미리 만들어 두고 숨겨 두어 진입 지연을 줄인다.
- **정지 화면 계열**(F1·F2·Alt+1·Alt+3): Rust가 캡처한 이미지를 오버레이 웹뷰에 배경으로 깔고, 판서는 Canvas에 그린다. 텍스트 입력은 웹뷰의 입력창을 그대로 써서 한글 조합 문제를 피한다.
- **실시간 계열**(Alt+2·F3): Rust 네이티브 경로. 확대 화면을 웹뷰로 보내지 않는다.
- **스마트 인식**: Windows UI Automation `ElementFromPoint` / macOS `AXUIElementCopyElementAtPosition`, 창 목록은 각 OS 창 목록 API. 정지 화면을 띄운 순간의 창·요소 목록을 미리 받아 두어 커서를 움직일 때 끊기지 않게 한다.
- **자기 창 제외**: 캡처·녹화에 이 앱의 말풍선·선택 테두리가 찍히지 않게 제외(macOS SCContentFilter, Windows `WDA_EXCLUDEFROMCAPTURE`). 판서 층은 녹화에 포함.
- **주요 Rust 의존성**: `windows`(UIA·WGC·Magnification·Media Foundation), `objc2` 계열(ScreenCaptureKit·AX·AVFoundation), `xcap`(기본 스크린샷), tauri 공식 플러그인(global-shortcut · store · autostart · single-instance · clipboard-manager).

### 13.7 프로토타입 합격선

- Windows 10/11과 macOS(맥미니 4K + FHD 듀얼)에서 13.2의 기능이 모두 작동.
- 단축키 → 화면 반응 0.15초 이내, 펜 지연 체감 없음(목표 p95 50ms), 4K 모니터에서 휠 확대가 끊기지 않음.
- F3: 1080p 30fps로 10분 녹화가 끊김 없이 저장되고 일반 플레이어에서 재생.
- 혼합 배율 듀얼 모니터에서 캡처 오차 1px 이하, 모드가 커서 모니터에 정확히 뜸.
- 대기 중 메모리 150MB 이하 [추정 목표], 단축키 재지정이 즉시 반영되고 재시작 뒤 유지.

### 13.8 난이도 총평과 일정 [추정]

- **전체 난이도: 중상.** 가장 어려운 셋 — ① F3 녹화(두 OS의 인코더 경로) ② Alt+2 실시간 확대(특히 맥, 공개 확대 API가 없음) ③ 혼합 배율 듀얼 모니터 좌표와 맥 권한. 쉬운 쪽 — 칠판, 도구 단축키, 트레이·설정(Tidy 재사용).
- **단계와 예상 작업일**(AI 에이전트와 함께, 두 OS 합산):
   1. 뼈대: 트레이·설정 창·전역 단축키·모니터별 오버레이 창 — 2일
   2. Alt+1 판서 · Alt+3 칠판 · 그리기 도구 — 3일
   3. F1 범위 캡처(스마트 인식) · F2 창 캡처 — 3일
   4. Alt+2 실시간 확대 — 2~3일
   5. F3 화면 녹화 — 3~4일
   6. 두 OS 다듬기 · 듀얼 모니터 검증 · 설치본(exe·dmg) — 2~3일
- 합계 약 15~18작업일. 녹화와 맥 실시간 확대가 늦어지면 그 둘을 프로토타입 끝으로 미루고 나머지를 먼저 완성한다.
- **개발 환경**(2026-11-24 확인): 맥미니(Apple Silicon, Xcode 있음, 4K + FHD 듀얼)에서 개발하고 맥 기능을 검증한다. Rust 도구는 아직 없어 설치가 필요하다. Windows 전용 기능(UI Automation·WGC·Magnification·Media Foundation)은 **사용자의 Windows PC**에서 시험한다.
   - 흐름: 맥에서 개발·커밋 → GitHub 비공개 저장소(Tidy와 같은 방식) → Windows PC에서 받아 `npm run tauri dev`로 실행 → 단계마다 시험 목록으로 확인 → 결과·오류를 대화로 전달.
   - Windows PC 한 번 준비: Git · Node 22 이상 · Rust(rustup, MSVC 도구 모음) · Visual Studio Build Tools(C++ 데스크톱 개발). Tidy를 빌드한 PC라면 대부분 이미 있다. WebView2는 Windows 11에 기본 포함.
   - 선택: Windows PC에 OpenSSH 서버를 켜 두면 빌드·로그 확인은 원격으로 할 수 있다(화면 조작 시험은 직접).
   - 시험할 Windows 조건: 배율 100%·150% 혼합 듀얼 모니터, PowerPoint 슬라이드 쇼 위, 표준 사용자 계정.
