## 1. 목적과 사용자

- **한 줄**: 발표자가 단축키 하나로 화면을 캡처하고, 확대하고, 그 위에 쓰는 오프라인 트레이 앱. Snipaste의 캡처 정확도와 아이캔 줌잇의 판서 손맛을 한 앱으로.
- **1차 사용자**: 발표자(교사 포함). 키보드·마우스 중심, 듀얼 모니터(교탁 + TV/전자칠판), 학교 PC(표준 사용자, 학교망).
- **성공 기준(1차)**: ① 5절 성능 목표를 학교 PC에서 통과 ② 6절 시나리오 카드 S1~S15 중 1차 범위 항목 전부 ○ ③ 발표자 3명이 10분 수업 시연을 다른 앱 없이 끝냄.

## 3. 핵심 사용 장면

1. **문제 풀이**: PPT 슬라이드 쇼 중 Alt+1 → 휠로 문제 부분 확대 → 빨간 펜(R)으로 풀이 → Esc. 다음 장으로 넘겼다가 "아까 그거" → Alt+1 후 직전 판서 불러오기.
2. **자료 공유**: 교재 PDF에서 F1 → 커서 아래 표가 자동 강조 → 클릭 → 한글(HWP)에 Ctrl+V. 범위가 마음에 안 들면 F1 후 "직전 범위"로 다시.
3. **시연 녹화**: F3 → 모니터 클릭 → 프로그램 사용법 시연(필요할 때 Alt+1로 표시) → F3 → MP4가 저장 폴더에.

### 4.12 창 항상 위 고정 (Windows만, P1)

PowerToys "항상 위"와 같은 기능. PowerToys가 없는 학교 PC에서도 쓰고, 이 PC에서는 PowerToys의 그 기능을 대신한다(같은 키 Alt+Shift+D). 구현은 PowerToys `src/modules/alwaysontop`(MIT)의 흐름을 따른다. **macOS는 하지 않는다**: 다른 앱 창의 층(window level)을 바꾸는 공개 API가 없다(손쉬운 사용 API는 위치·크기만 바꿈). 맥에서는 설정·트레이에서 이 줄을 숨긴다.

| ID | 우선 | 요구사항 | 합격 기준 | 근거 |
|---|---|---|---|---|
| R-TOP-1 | P1 | **키 한 번 = 지금 앞에 있는 창 고정, 한 번 더 = 풀기.** 대상 = `GetForegroundWindow`의 최상위 창. 바탕 화면·작업 표시줄·시작 메뉴·screen-ink 자기 창·숨김·최소화·cloaked 창은 건너뛰고 말풍선으로 이유. 고정 = `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE·SWP_NOSIZE·SWP_NOACTIVATE)` + `SetProp`(screen-ink 표시), 풀기 = `HWND_NOTOPMOST` + `RemoveProp`. **원래부터 맨 위인 창**(앱이 스스로 건 것)은 건드리지 않고 "이 창은 원래 맨 위에 있어요" | 크롬·한글·PowerPoint·탐색기·카카오톡에서 고정/풀기 100회 오류 0, 다른 창을 눌러도 위에 남음 | PowerToys `AlwaysOnTop.cpp` `ProcessCommand`·`PinTopmostWindow`(PowerToys는 원래 맨 위인 창도 풀어 버림 → 표시가 있는 창만 풀도록 바꿈) |
| R-TOP-2 | P1 | **고정 표시**: 창 둘레 테두리(기본 켬, 테마 강조색, 4 px, 끌 수 있음) + 말풍선 "‘Chrome’을 맨 위에 고정했어요 · 한 번 더 누르면 풀려요"(앱 이름만, 창 제목은 쓰지 않음). 테두리 창은 클릭 통과·포커스 안 받음 + `WDA_EXCLUDEFROMCAPTURE`(캡처·녹화·화면 공유에 안 찍힘). 위치는 `SetWinEventHook`(`WINEVENT_OUTOFCONTEXT` — 다른 앱에 주입 없음)으로 이동·크기·최소화·숨김·닫힘을 따라가고, 경계는 R-CAP의 DWM 확장 프레임 코드를 같이 씀 | 창을 끌거나 최대화해도 테두리가 16 ms 안에 따라옴, F1 캡처에 테두리 0 px | PowerToys `WindowBorder`·`SubscribeToEvents` |
| R-TOP-3 | P1 | **안전·정리**: 관리자 권한 창은 UIPI로 막힘 → "관리자 권한 창이라 고정할 수 없어요". 고정한 창이 닫히면 목록에서 자동으로 뺌. 앱을 끝낼 때 모두 풀기. **비정상 종료 뒤 다음 시작 때 표시가 남은 창을 `EnumWindows`로 찾아 풀기**(창이 영원히 맨 위에 남지 않게). 전체 화면 D3D 게임 중에는 키를 무시(PowerToys 기본과 같음). 트레이 "고정한 창 모두 풀기 (n)" | 작업 관리자로 강제 종료 → 다시 실행하면 남은 고정 0 | PowerToys `UnpinAll`·`CleanUp`·`detect_game_mode` |
| R-TOP-4 | P1 | **PowerToys와 같이 있을 때**: PowerToys 항상 위가 실행 중(`PowerToys.AlwaysOnTop`)이고 키가 같으면 R-KEY-2로 "PowerToys에서 ‘항상 위’를 끄거나 screen-ink 키를 바꾸세요". PowerToys가 고정한 창(표시 `AlwaysOnTop_Pinned`)은 screen-ink가 풀지 않고 "PowerToys가 고정한 창이에요" | 둘 다 켠 상태에서 상태가 엇갈리는 창 0 | 이 PC 설정(PowerToys 항상 위 = Alt+Shift+D, 테두리 켬) |
| R-TOP-5 | 후속 | 고정한 창 투명도(PowerToys Win+Ctrl+= / −): `WS_EX_LAYERED` + `SetLayeredWindowAttributes`, 풀 때 원래 값 복원 | — | 하드웨어 가속 창 깜빡임 위험이 있어 1차에서 뺌 |

## 8. 검증 계획

- 매 단계 끝: 해당 지표(M1~M9)를 학교 PC에서 재고 `bench/results/`에 CSV를 쌓는다. 목표 미달이면 6절 "다시 정할 조건"을 따른다.
- 시나리오 카드 S1~S15([벤치마크 README](benchmark/README.md) 6절)를 Snipaste·아이캔 줌잇·ZoomIt·screen-ink에 같은 순서로 해 보고 ○/△/×로 기록한다.
- 혼합 배율(100%+150%) 시험은 디스플레이 설정만 바꿔 같은 PC에서 한다.
- **인식**: 시험대 RB-01~20을 단계 3 중간·끝·단계 7에 돌리고, 스냅숏 재생 시험은 커밋마다 CI에서 돈다(Top-1·Top-3·경계 오차가 기준선보다 떨어지면 실패). Snipaste 대조는 같은 커서 점 집합으로 단계 3 끝(G4)과 단계 7에 한다.
- **단축키**: 입력표와 앱이 같은 시험 자료로 59칸 × 2 OS 판정이 같은지 본다(G1).
- 릴리스 체크리스트: R-NET-2(네트워크 0 검사) · R-LOG-1(로그에 창 제목 0건) · 표준 사용자 실행 · 백신 오탐 확인.
