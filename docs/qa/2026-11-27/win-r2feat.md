### 추천 묶음에서 남은 현상

- **앱을 켜고 첫 캡처 전에 적용**하면 설정 창이 ‘적용 중’에서 멈추고 Windows도 응답 없음으로 판정했다. 발표용 기본과 Snipaste 습관에서 재현했다. 사본을 다시 켜서 영역 캡처를 한 번 복사한 다음 같은 설정으로 들어가면 세 묶음 모두 응답했다. 결과 섬을 띄우는 시점과 연관된 현상으로, W5의 창 표시 변경(`9070297`)을 합친 빌드에서 재확인이 필요하다.
- **다른 앱이 점유한 예전 키**는 되돌리기 요청이 성공했다고 반환돼도 이전 값이 돌아오지 않았다. 예를 들어 왼손 묶음을 되돌린 뒤 영역·방금 범위·전체의 값은 각각 Alt+Q·Alt+A·Alt+S로 남았다. 사본에서 확인한 등록 거절은 F1·F3·Shift+F1·Ctrl+F1이었다. 앱의 겹침 안내에 표시된 이름은 Snipaste였다.
- 화면에서 되돌리기 응답의 실제 키와 적용 전 값을 비교하도록 고쳤다. 최종 사본에서 복원이 덜 끝났다는 안내를 확인했다. 네 키가 모두 거절됐을 때도 건너뛴 개수가 표시됐고, 변경이 없어 되돌리기 단추는 생기지 않았다. 점유 중인 키의 **설정값 자체를 보존해 복원하는 작업**은 단축키 서비스에 남는다.

## W13 재확인

W5 수정(`9070297`)을 포함한 `7da7852`에서 첫 캡처 전 ‘적용 중’ 멈춤은 **3회 중 0회**였다. `npm run app:build -- --no-bundle`로 만든 릴리스 사본을 매회 새로 켜고, 독립된 WebView2 프로필과 같은 초기 단축키를 사용했다. ‘발표용 기본’에도 실제 변경이 생기도록 사본의 휴대용 설정에서 창 찍기를 `Ctrl+Win+F10`으로 준비했다.

| 회차 | 적용 경로 | 적용 뒤 같은 묶음의 미리보기를 다시 연 결과 |
|---|---|---|
| 1 | 설정 › 단축키 › 발표용 기본 | 창 찍기가 F2로 바뀌었고 ‘지금 쓰고 있는 묶음과 같아요’가 표시됐다. |
| 2 | 설정 › 단축키 › Snipaste 습관 | 창 찍기 F2와 화면 녹화 F4가 적용됐다. 화면에 고정 F3와 고정 숨기기·보이기 Shift+F3만 겹침으로 남았다. |
| 3 | 첫 실행 ④ › Snipaste 습관 | ‘2개 키는 겹쳐서 바꾸지 못했어요’가 표시됐다. 다시 연 미리보기에는 2회차와 같은 두 키만 남았다. |

세 회차 모두 실제 설정 창이 `WM_NULL`에 응답했고 `IsHungAppWindow`는 거짓이었다. 시작 기록은 매번 ‘전역 단축키 등록 12개, 실패 4개’였고 거절된 키는 F1·F3·Shift+F1·Ctrl+F1이었다. 적용 뒤에는 결과 섬 이벤트와 UI가 섬을 숨긴 기록이 순서대로 남았다. Snipaste는 계속 실행했다. 이번 재확인에서는 추가 코드 수정 없이 마쳤다.
