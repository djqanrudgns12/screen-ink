## F1 범위 손보기 (`3-SEL-ADJUST`)

각 첫 범위를 확정하고 해당 동작을 한 번 실행한 뒤 Enter로 복사했다. 크기는 PNG에서 읽었다. 두 화면에 걸친 검사는 Alt로 자석을 꺼 비교했다.

| 동작 | 4K 200% | FHD 100% | 4K → FHD 걸친 범위 |
|---|---:|---:|---:|
| 기준 범위 | 600×440 | 320×190 | 600×360 |
| 범위 안 끌기 | 600×440 | 320×190 | 600×360 |
| 오른쪽 변만 | 760×440 | 260×190 | 660×360 |
| 아래 변만 | 600×380 | 320×285 | 600×315 |
| 왼쪽 위 귀 | 700×520 | 360×220 | 650×390 |
| 오른쪽 위 귀 | 700×520 | 370×230 | 650×390 |
| 왼쪽 아래 귀 | 700×540 | 360×250 | 650×410 |
| 오른쪽 아래 귀 | 700×540 | 380×270 | 650×410 |
| 오른쪽 변을 반대편 너머로 | 160×440 | 60×190 | 70×360 |
| 바깥에서 다시 그리기 | 340×300 | 150×130 | 320×180 |
| 같은 변을 메모장 경계 근처까지 | 자석 288×180 · Alt 282×180 | 자석 315×140 · Alt 311×140 | 기준 끌기는 자석 켬 599×360 · Alt 600×360 |

- 범위 안은 이동 커서, 오른쪽 변은 좌우 양쪽 화살표, 아래 변은 상하 양쪽 화살표였다. `GetCursorInfo`에서 각각 시스템 커서 32646·32644·32645를 두 배율에서 확인했다. 네 귀와 네 변 가운데의 손잡이가 화면에 보였다. 혼합 범위의 오른쪽 변에 포인터를 한 번에 옮겼을 때 십자 커서가 남았지만 11px 더 움직이자 좌우 화살표로 바뀌었다. 두 정지 이미지가 맞물렸고 복사 PNG의 양끝에서 왼쪽 `#E6EDF4`와 오른쪽 `#6B8D76`을 확인했다.
- FHD에서 오른쪽 변을 물리 x4198까지 끌면 메모장 경계 x4202에 붙었다. 4K에서는 변을 x1602까지 끌면 메모장 경계 x1608에 붙었다. 같은 끌기에 Alt를 누르면 각각 4px, 6px 작은 폭이었다.

## 고친 Windows 결함과 검사

- Windows에서 F2를 두 번 누르면 `No current window`가 나왔고 클립보드 변경이 없었다. 같은 활성 메모장에 `Shift+F2`를 누르면 정상 복사됐다. F2 오버레이를 닫을 때 그 오버레이나 안내 섬이 아직 전경이면 처음 활성 창으로 초점을 돌려주도록 했다. 캡처 도중 다른 앱이 전경이 됐거나 원래 창이 사라진 경우는 건드리지 않는다.
- 안내 섬이 뜬 직후 Esc가 캡처로 전달되지 않는 경우가 있었다. Windows에서만 WebView2 컨트롤러를 미리 표시 상태로 두고 섬의 최상위 창을 포커스 없이 보이거나 숨기도록 했다.
- 최종 사본의 두 언어에서 섬이 보일 때 Esc 한 번으로 F2가 닫혔다. 오른쪽 시험 HTML에 커서를 놓고 F2를 두 번 누르면 활성 메모장 PNG 2642×1422를 복사했다. 최종 사본에서 단색 칩 클릭과 Tab 타원도 다시 확인했다.
- Windows 고침 커밋은 `628bfdc`이다.
- `npm.cmd run app:build -- --no-bundle` 통과. `cargo test -p ink-platform-windows` 통과(52개 통과, 실패 0개, 기본 제외 11개). `cargo clippy -p ink-platform-windows -p tauri-plugin-screen-ink --all-targets -- -D warnings` 통과.
- 사람 확인이 필요한 항목은 #21·#25·#29와 #30의 캡처 제외 섬·HUD·테두리 외관, 실제 보호 화면에서의 #17이다. OS 설정 변경은 사람 승인 필요. 자동 업데이트 안내의 실제 송수신, MSIX 설치와 성능 계측은 미실행이다.
