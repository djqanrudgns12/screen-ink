# 슉쇽 2차 고도화 PRD — 2026-11-27

- 기준: 브랜치 `feat/foundation`, 1차 PRD [docs/PRD.md](../../PRD.md) v3.0. 이 문서는 1차 위에 얹는 **2차 요구**이고, 1차의 공통 계약(포트, 좌표 = 가상 화면 물리 px·왼쪽 위 원점, `Case`, `InkClient`, `nativeFrame`)은 바꾸지 않는다. 새 포트 메서드는 기본 구현을 둔다.
- 요구 ID는 `R2-<영역>-<번호>`. 우선순위: **P0** 이번 묶음에 반드시 · **P1** 이번 묶음에 넣되 P0 뒤 · **P2** 다음 묶음.
- 출처: 2026-11-27 사용자 요청 11가지(아래 각 절 첫 줄에 원문 요지).
- 표기: **[결정 대기]** 사용자가 고를 것 · **[확인 필요]** 아직 사실 확인 안 한 가정.

## 0. 원칙(이번 묶음 전체)

1. **두 OS 동등(R2-OS-0)**: 모든 기능은 맥·Windows 둘 다 같은 모양으로 낸다. 한쪽만 되는 것은 기술상 불가능할 때만, 그 까닭을 §10 표에 적는다.
2. **맥 감성·세련**: 여백·정렬·글자 위계·아이콘 획을 맞춘다. 화면 말투는 [04 화면](../../prd/04-screens.md)의 짧은 존댓말("~해요").
3. **개인정보**: 로그·PDF·사례 파일에 창 제목·파일 이름·사용자 이름을 넣지 않는다(1차 R-LOG-1 그대로).
4. **네트워크**: 1차 R-NET-1·2(앱이 스스로 통신하지 않음, 통신은 OS가) 정신을 지킨다. 자동 업데이트만 예외 규칙을 §9에 둔다.
5. **분업**: 총괄(Claude)은 설계·계약·핵심 로직·검수를 맡고, 제미나이(Antigravity, 네온 오케스트레이터)는 화면 구현·이식·시험 보강·조사·문서 잡무를 맡는다. 코덱스는 쓰지 않는다(사용자 지시). §12 배분표.

## 1. 첫 실행 권한 안내 카드 + 설정 점검 (R2-ONB)

> 요청 1: 손쉬운 사용·화면 기록 두 권한을 처음에 카드 슬라이드로 하나씩 켜게, 켤 때마다 표시, 다 켜야 넘어가게. 설정에서도 둘 다 켰는지 점검.

**왜**: 맥은 화면 기록이 없으면 캡처·확대가 빈 화면이고, 손쉬운 사용이 없으면 스마트 범위(AX)·휠 가로채기·자동 입력이 안 된다. 지금은 첫 실행 시트(`FirstRunSheet.svelte`) 한 장 안에 안내가 섞여 있고, 권한 섬(M10)은 일이 터진 뒤에 뜬다.

| ID | 우선 | 요구 | 수용 기준 |
|---|---|---|---|
| R2-ONB-1 | P0 | 첫 실행 = **카드 슬라이드**(가운데 시트, 한 장씩): ① 반가워요(슉쇽 세 가지 일 — 캡처·판서·확대) → ② **화면 기록** → ③ **손쉬운 사용** → ④ 단축키 세 개(지금 시트의 "먼저 이 셋만") → ⑤ 준비 끝. 점 표시(●○○○○)와 [다음]/[이전]. | 첫 실행에서 5장이 차례로 보이고, 키보드(←→·Enter·Esc 금지)로도 넘어간다 |
| R2-ONB-2 | P0 | 권한 카드는 **[켜러 가기]** → 시스템 설정의 그 칸을 연다(`permissions::request_*`, M10 그대로). 앱은 1초마다 상태를 다시 읽어 **켜지는 순간 카드에 체크 표시**(초록 원·"켜졌어요")와 짧은 움직임. | 시스템 설정에서 켜면 2초 안에 카드가 바뀐다(손쉬운 사용은 실시간, 화면 기록은 아래 3) |
| R2-ONB-3 | P0 | **화면 기록**은 macOS가 앱을 다시 시작해야 반영되는 경우가 있다 → 켠 뒤에도 미확인이면 카드에 [다시 시작해서 확인](`app.restart()`)을 보이고, 다시 켜졌을 때 **그 카드부터 이어서** 연다(진행 위치를 설정 `onboarding.step`에 저장). | 다시 시작 뒤 ②번 카드가 체크된 채로 열린다 |
| R2-ONB-4 | P0 | **다 켜야 넘어간다**: ②·③이 체크돼야 [다음]이 켜진다. 빠져나갈 길은 하나만 — 카드 아래 작은 글씨 "나중에 할게요(일부 기능이 안 돼요)" → 확인 한 번 뒤 넘어감, 트레이 아이콘에 주황 점이 남는다(사용자 결정 존중, 갇히지 않게). [결정 대기: 완전 차단 vs 이 탈출구 — 기본안 = 탈출구 있음] | 두 권한이 없으면 [다음]이 회색, 탈출구는 확인 창을 거친다 |
| R2-ONB-5 | P0 | **Windows**: 권한 카드 대신 같은 자리에 ② "단축키 겹침 점검"(PrintScreen·Win+Shift+S·다른 캡처 앱, 1차 진단 그대로)과 ③ "시작할 때 켜기"를 둔다 — 카드 수·모양은 같다. | Windows 첫 실행도 5장, 권한 문구가 나오지 않는다 |
| R2-ONB-6 | P0 | **설정 › 일반 › 권한 점검** 묶음: 줄마다 상태(켜짐 ✓ / 꺼짐 ! / 다시 시작 필요), [열기] 단추, 위에 한 줄 요약("둘 다 켜져 있어요"). 설정을 열 때·창이 앞으로 올 때 다시 읽는다. Windows는 같은 자리에 단축키 겹침·시작 프로그램 점검. | 권한을 끄면 설정 창에 2초 안에 반영 |
| R2-ONB-7 | P1 | 업데이트·재서명 뒤 권한이 풀린 것을 감지하면(M10 `screen_revoked`) 첫 실행 카드의 그 장만 다시 연다(섬 대신). | 재서명 시나리오 fake 시험 |

**설계 메모(총괄)**
- 서비스: `InkService::onboarding_state()` → `{ step, screen, accessibility, needsRestart }`(새 상태 필드, `Permissions` 재사용). 상태 읽기는 기존 `SystemProbe::permissions()`. 1초 감시는 시트가 열려 있을 때만(창 쪽 타이머 → `refresh_permissions` 명령).
- 화면: `FirstRunSheet.svelte`를 `Onboarding.svelte`(카드 틀) + 카드 5개 부품으로 나눈다. 카드 그림은 아이콘 세트(§3 결정)로.
- 시험: fake `ProbeScene.permissions`로 켜짐·꺼짐·다시 시작 흐름, UI 시험(`node --test` 모델 + 미리보기 `?onboarding=1&perm=…`).

## 4. 단축키 바꾸기 중 F 키가 캡처를 실행하는 버그 (R2-KEY-REC)

> 요청 4: 단축키를 바꾸려고 녹화 중 fn+F1을 누르면 캡처가 실행돼 안 바뀐다. 확실히 보완.

**[완료 2026-11-27 — R2-KEY-REC-1·2·4]** 서비스 `begin_shortcut_capture`/`end_shortcut_capture`, 명령 `shortcut_capture`(20초 시간 제한·설정 창 blur/닫힘에 되살림), `SettingsWindow`가 녹화 상태를 알림, 시험 `usecases.rs` `단축키_녹화_중에는_…`·`단축키_녹화_중_잠시_끄기를_…`. 남음: 맥 fn+F1 실기·R2-KEY-REC-3·5(녹화 칸 문구).

**원인(확인함)**: 실제 앱의 단축키 녹화(`ShortcutsPage.svelte`)는 웹뷰 `keydown`으로 키를 받는데, 그동안 **전역 단축키가 그대로 등록돼 있다** → OS가 F1을 먼저 가로채 캡처를 실행한다. 미리보기(`Preview.svelte`)만 녹화 중 `setHotkeysEnabled(false)`를 불러서 시험·미리보기에서는 안 보였다. Windows도 같은 버그(전역 `RegisterHotKey`가 먼저 가로챔).

| ID | 우선 | 요구 | 수용 기준 |
|---|---|---|---|
| R2-KEY-REC-1 | P0 | 서비스 `begin_shortcut_capture()` / `end_shortcut_capture()`: 녹화하는 동안 **모든 전역 단축키(잠시 끄기 칸 포함)를 조용히 푼다** — 섬을 띄우지 않고 상태 `hotkeysEnabled`도 바꾸지 않는다(사용자가 끈 것과 다름). | fake: 녹화 중 F1 사건이 캡처를 열지 않는다 |
| R2-KEY-REC-2 | P0 | **꼭 되살림**: 녹화 끝·Esc·다른 줄 클릭·설정 창 닫힘·창이 뒤로 감(blur)·**20초 시간 제한**·웹뷰가 죽음 중 무엇이든 먼저 오면 다시 등록. 이중 호출에 안전(세는 방식 아님, 상태 한 개). | 시험: 녹화 시작 후 창 닫기 → 전역 키 다시 등록 |
| R2-KEY-REC-3 | P0 | 맥 F 키: `fn`+F1은 웹뷰에 `F1`로 온다 — 그대로 저장. "표준 기능 키"가 꺼져 있어 밝기 키로 가 버리면 녹화 칸에 "fn과 함께 눌러 보세요" 한 줄. 밝기·소리 같은 미디어 키는 받지 않는다고 알린다. | 맥에서 fn+F1 → "F1" 저장(실기) |
| R2-KEY-REC-4 | P0 | 녹화 중 전역 키를 못 푼 경우(OS 거절)에도 앱 안 처리기(`on_hotkey`)가 녹화 상태를 보고 그 사건을 무시한다(이중 안전). | fake 시험 |
| R2-KEY-REC-5 | P1 | 녹화 칸 UX: "새 키를 눌러요 · Esc 취소 · ⌫ 비우기", 겹치면 그 자리에서 어느 기능과 겹치는지 + [바꾸기]. | 모델 시험 |

**분업**: 서비스·명령·되살림 로직 = 총괄(핵심). 녹화 칸 UX 문구·화면 = 제미나이.

## 13. 순서(물결)

| 물결 | 내용 | 끝 조건 |
|---|---|---|
| W0 결정 | 아이콘 10세트·PDF 5시안·글꼴 견본(제미나이 작업 중) → **사용자 고름** · R-NET 개정 승인 · 권한 탈출구 여부 | 결정 4개 |
| W1 기반(결정과 무관, 바로 시작) | S1 단축키 녹화 버그 · S3 다국어 틀 · S2 권한 상태 계약 · S8 가림 알고리즘 + 합성 사례 · S10 동등 표 | 각 시험 통과·커밋 |
| W2 화면 | S2 카드·점검 · S4 아이콘 이식·툴바 · S5 트레이 · S6 글꼴 적용 · S11 설명서 · S3 문자열 옮기기·영어 | 미리보기 전 화면 눈 확인 |
| W3 기능 | S7 PDF · S9 업데이트(맥 Sparkle·Windows 틀) · S8 회귀 표 | 두 OS 결과(맥 실기, Windows는 표) |
| W4 마감 | 동등 표 갱신·인수인계·진척 표·Windows 실기 넘김 | 인수인계 문서 |

**사람이 할 일(에이전트가 대신 못 함)**
1. 결정 4개(위 W0).
2. 맥 권한 켜기는 첫 실행 카드에서 사용자가 직접(에이전트는 권한 창을 누르지 않는다).
3. Sparkle EdDSA 키 만들기(`generate_keys`) + Bitwarden `ops` 백업, 자체 서명 인증서 p12 Bitwarden 백업.
4. 릴리스 게시 확인(초안 → 공개).

## 14. 검증

- 공통: `cargo test`(6개 크레이트) · `clippy -D warnings` · `npm test` · `npm run check` · `npm run progress -- --check`.
- 새 검사: 다국어 키 검사(§2-7), 업데이트 통신 0 확인(끈 상태, §9-4), PDF 글자 추출(§7-2), 합성 사례 맞춤률(§8-5).
