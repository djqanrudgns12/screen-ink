# 02. 스마트 로직 명세

2026-11-25 · PRD v3.0 부속 · "알아서 맞게 고르고, 틀리면 바로 되돌릴 수 있게"가 원칙이다. 모든 규칙은 **순수 함수**로 `ink-domain`에 두고(입력 = 정지 순간의 스냅숏, 출력 = 결정) 단위 시험한다([03-architecture](03-architecture.md)). 수치는 첫 기본값이며 벤치마크(M1·M5·M8)로 조정한다.

## 0. 공통 원칙

1. **정지 순간 스냅숏**: 단축키를 받은 순간 `FrameSnapshot`(모니터별 이미지) · `WindowCatalog`(창 목록) · `MonitorLayout`(배치·배율)을 한 번 찍고, 그 모드가 끝날 때까지 이 값만 본다. 모드 중에 바깥 화면이 바뀌어도 판단이 흔들리지 않는다.
2. **좌표는 하나**: 모든 계산은 "물리 픽셀 가상 화면" 좌표(`PhysPoint`, `PhysRect`). 웹뷰에 그릴 때만 모니터 배율로 바꾼다. 변환 함수는 `geometry::to_logical(rect, monitor)` 하나뿐이다.
3. **느리면 포기하고 다음 단계로**: 외부 질의(UI Automation 등)는 시간 제한이 있고, 넘으면 더 단순한 방법으로 내려간다. 화면은 절대 멈추지 않는다.
4. **추측은 보여 주고, 확정은 사용자가**: 강조·추천·보정은 모두 화면에 먼저 보이고, 한 번의 조작(휠·Tab·Ctrl+Z)으로 되돌릴 수 있다.
5. **개인정보**: 스마트 로직이 창 제목·글자를 읽더라도 메모리 안에서만 쓰고 기록·로그·통계에 남기지 않는다.

## 1. 범위 인식 (F1)

> **v2.0**: 후보를 어디서 얻는지(근거 5개 융합 · 이미지 분석 · 진입 때 색인 · 멈추지 않는 질의)는 [08-smart-capture](08-smart-capture.md)가 우선한다. 아래 §1.1의 사슬 다듬기 규칙, §1.3~1.6은 그대로 쓰고, §1.2의 "커서 이동마다 질의"는 08 §4.7의 "진입 때 색인, 이동 때 메모리"로 바뀐다.

### 1.1 후보 사슬 만들기

```
커서 점 p
 └ 요소 사슬(깊은 것부터): UIA ElementFromPoint(p) → ControlViewWalker로 부모를 따라 창까지
 └ 창: 정지 순간 창 목록에서 Z 순서로 p를 포함하는 첫 창
 └ 모니터: p가 있는 모니터(작업 영역 → 모니터 전체)
 └ 가상 화면 전체
= Chain[0..n]  (Chain[0] = 가장 작은 조각)
```

창 목록 거르기(정지 순간 1회, `WindowCatalog::filter`):

| 규칙 | 이유 |
|---|---|
| 보이지 않음 · 최소화 · 크기 0 | 고를 수 없음 |
| `DWMWA_CLOAKED` | 다른 가상 데스크톱·숨은 UWP 창(xland/ScreenCapture 방식) |
| `IsHungAppWindow` | 멈춘 앱에 질의하다 굳지 않게(Snipaste 방식) |
| 자기 앱 창(오버레이·말풍선·설정) | 자기 자신이 잡히지 않게 |
| 감지 제외 앱 목록 | 사용자가 뺀 앱(예: 녹화 프로그램 테두리) |
| 경계 = `DWMWA_EXTENDED_FRAME_BOUNDS` | 그림자 뺀 실제 경계 |

요소 사슬 다듬기(`chain::normalize`):

- 화면 밖으로 나간 사각형은 모니터에 맞춰 자른다.
- **부모와 사각형이 같은(±1px) 단계는 뺀다** → 휠을 한 칸 돌리면 화면의 강조가 반드시 바뀐다.
- 4×4px보다 작은 요소는 뺀다.
- 창 경계를 넘는 요소는 창 경계로 자른다.

### 1.2 질의 시간 제한과 대체

| 단계 | 시간 제한 | 넘으면 |
|---|---|---|
| UIA `ElementFromPoint` + 부모 따라가기 | 30 ms(커서 이동마다, 16 ms 묶음) | MSAA `AccessibleObjectFromPoint` 시도 |
| MSAA | 20 ms | 창 단위만 |
| 같은 앱에서 150 ms 넘는 일이 2번 | — | **그 앱을 "느린 앱"(창 단위만)에 자동 추가**하고 말풍선으로 알림(설정에서 뺄 수 있음) |

UIA 질의는 전용 COM 스레드에서 하고, 결과는 `RuntimeId`로 캐시한다(같은 요소 위에서 커서가 움직이면 재질의하지 않음). 커서가 빨리 움직이면 마지막 질의만 살린다.

### 1.3 깊이 기억 (휠로 고른 "층"을 유지)

교사는 표에서 "행" 단위로 고르기 시작하면 다른 행으로 옮겨도 행을 원한다. 그래서 휠로 고른 단계를 숫자가 아니라 **"어떤 종류의 조각인지"**로 기억한다.

```
level_intent = { control_type: Chain[level].control_type, depth_from_window: k }
커서가 옮겨 가면: 새 사슬에서 같은 control_type을 가진 단계 → 없으면 창에서 같은 거리(k) → 없으면 가장 깊은 단계
창이 바뀌면 level_intent 초기화
```

시험: "표의 2행을 휠로 고른 뒤 3행으로 옮기면 3행 전체가 강조된다", "다른 창으로 옮기면 가장 작은 조각부터 다시".

### 1.4 모서리 자석 (드래그)

- 후보 경계 = 정지 순간 모든 창·요소 사각형의 네 변 + 모니터 변 (+ P1: 이미지 윤곽선).
- 끌어당김 거리 = **8 논리 px × 모니터 배율**. 가장 가까운 한 변에만 붙고, 붙은 변에 하늘색 안내선.
- 붙은 뒤 12 px 넘게 움직여야 떨어진다(히스테리시스 — 경계 근처에서 깜빡이지 않게).
- **Alt를 누르는 동안 자석 끔**. 방향키 미세 조정은 자석을 쓰지 않는다.

### 1.5 키 조작 (범위가 정해진 뒤)

| 키 | 동작 | 규칙 |
|---|---|---|
| ←↑→↓ | 범위 1px 이동 | 가상 화면 밖으로 나가지 않음 |
| Ctrl+방향 | 그쪽 변을 1px 늘림 | |
| Shift+방향 | 그쪽 변을 1px 줄임 | 최소 1×1 |

| `,` `.` | 지난 범위 앞뒤 | 기록 N개(기본 20), 이미지 없이 사각형만 |
| Ctrl+A | 커서 모니터 전체 | 한 번 더 = 가상 화면 전체 |
| `` ` `` | 커서 포함 토글 | 크기 배지에 "커서 포함" |

### 1.6 다음 행동 추천 (추천 칩 한 칸)

범위가 정해지면 마지막 칸에 **하나만** 추천한다(버튼 위치가 흔들리지 않게 늘 같은 자리).

| 판단 근거 | 추천 | 1차 동작 |
|---|---|---|
| 범위 안 UIA 요소에 Table/DataGrid | "표 같아요 · 표로 복사" | 칩만 보임, 누르면 "다음 버전" 안내 |
| 범위 픽셀의 92% 이상이 한 색(±6) | "한 가지 색이에요 · HEX 복사" | **동작함**(C와 같음) |
| 범위 안 Text/Document 요소 비율 높음 | "글자가 있어요 · 글자 복사(OCR)" | 칩만 |
| QR 찾기 무늬(3개 위치 표식) | "QR이 있어요 · 내용 보기" | 칩만 |
| 해당 없음 | 칩 없음 | — |

판단은 정지 이미지와 이미 받은 요소 정보로만 하고(추가 질의 없음), 50 ms 안에 못 끝내면 칩을 띄우지 않는다.

## 2. 창 캡처 (F2)

- 커서 아래 창(1.1의 창 규칙) 강조 → 클릭 = 그 창을 WGC `CreateForWindow`로 한 장. 노란 테두리 끄기(`SetIsBorderRequired(false)`), 지원 안 되는 OS는 테두리가 생기기 전에 첫 프레임만 받는다.
- **F2 두 번(400 ms 안) = 지금 활성 창**(강조 없이 바로).
- 결과가 **전부 검정**(보호 콘텐츠)이면 "이 창은 가져올 수 없어요" — 빈 이미지를 클립보드에 넣지 않는다.
- 최소화된 창은 고르지 않는다(목록에서 빠짐). 둥근 모서리 창은 투명 배경 PNG.
- WGC 실패 → `PrintWindow(PW_RENDERFULLCONTENT)` → `PrintWindow(0)` → `BitBlt`(xcap 순서). 어느 단계로 찍었는지 로그에 남긴다(디버그용, 창 제목 없이).

## 3. 판서·칠판 (Alt+1 · Alt+3)

### 3.1 진입

커서 모니터의 정지 이미지(F1과 같은 스냅숏 경로) → 미리 만든 그 모니터 오버레이에 깐다 → 말풍선 "판서 · 빨강 · 펜 4px" 1.2초. 직전 판서가 보관돼 있으면 말풍선 끝에 "Ctrl+Shift+R 이전 판서".

### 3.2 획 처리 파이프라인

```
포인터 이벤트(합쳐진 이벤트 getCoalescedEvents 포함)
 → 좌표: 화면 → 문서(확대·이동 역변환)
 → 떨림 보정: One Euro 필터 (끔 / 약: mincutoff 1.0 beta 0.007 / 강: mincutoff 0.6 beta 0.004, dcutoff 1.0)
 → 점 줄이기: RDP ε = 0.5 문서 px (작은 한글 점·획은 길이 6px 미만이면 보정·줄이기 건너뜀)
 → 그리기: 웹 Canvas, 이미 끝난 획은 아래층 비트맵에 굳히고 지금 획만 다시 그림
 → 펜 압력이 있으면 굵기 × (0.6 + 0.8 × pressure)
```

굵기는 **화면 기준**으로 고정: 확대 ×2에서 4px로 쓰면 문서에는 2px로 저장돼, 확대를 풀어도 화면에서 본 비율 그대로 남는다(ZoomIt의 `g_RootPenWidth = 펜 / 배율`과 같은 생각).

### 3.3 도형 보정

| 상황 | 규칙 |
|---|---|
| 직선·화살표 각도가 수평·수직 ±4° 이내 | 정확히 수평·수직으로(설정에서 끔) — 말풍선 "수평으로 맞췄어요" |
| 펜 획 끝에서 **0.5초 멈춤**(움직임 ≤ 2px) | 후보 판정: 직선(최대 벗어남 < 길이 6%) → 원·타원(타원 맞춤 오차 < 8%) → 사각형(RDP 꼭짓점 4개, 각 90°±12°) 순서로 첫 번째 통과 도형으로 바꿈. 말풍선 "직선으로 바꿨어요 · Ctrl+Z로 원래 획" |
| 판정 실패 | 원래 획 그대로(아무 말 없음) |
| Ctrl+Z 직후 | 보정 전 원래 획으로 돌아감(보정은 별도 실행 취소 단계) |

### 3.4 스마트 우클릭과 이동

| 상태 | 우클릭 | 좌클릭 |
|---|---|---|
| 확대 안 함(×1) | **판서 끝내기**(보관 규칙 3.6) | 그리기 |
| 확대 중(>×1) | **손(이동) 모드** — 마우스를 움직이는 만큼 화면 이동 | 손 모드면 **다시 판서**, 아니면 그리기 |

아이캔 줌잇 사용자의 "우클릭으로 이동 → 좌클릭으로 판서" 습관을 그대로 살리면서, 확대하지 않았을 때는 ZoomIt·Snipaste처럼 우클릭으로 나갈 수 있다. 확대 상태에서 커서를 가장자리 30px 안으로 밀어도 화면이 따라 움직인다(12px/프레임).

### 3.5 확대(휠)

단계 1 → 1.25 → 1.5 → 1.75 → 2 → 3 → 4 → 6 → 8. 커서 아래 점이 화면에서 제자리에 있도록 이동량을 계산한다(`t' = c − s'·(c − t)/s`). 문서 밖이 보이지 않게 가둔다. 첫 휠은 설정의 "시작 확대 배율"(기본 1.75)로 바로 간다.

### 3.6 나가기와 보관

- Esc(설정 "한 단계씩"이면: 글자 입력 → 고르기 해제 → 확대 해제 → 나가기 순서) · 확대 안 한 상태의 우클릭 · 같은 모드 키.
- "나갈 때 판서 보관"이 켜져 있으면 획 목록과 **정지 이미지 ID·모니터 구성 지문**을 메모리에 1장 보관.
- 다음 판서에서 Ctrl+Shift+R: 같은 모니터·같은 구성이면 그대로, 배율만 바뀌었으면 비율대로 옮기고 "배율이 바뀌어 크기를 맞췄어요", 다른 모니터면 "다른 모니터라 불러올 수 없어요".

### 3.7 글자(T)

웹뷰 입력 상자를 그 자리에 띄워 IME를 그대로 쓴다. **조합 중(`compositionstart`~`compositionend`)에는 도구·색 단축키를 무시**한다. 색 = 지금 펜 색, 크기 = 굵기 × 6. Esc·바깥 클릭 = 입력 끝(빈 글자는 만들지 않음). 고르기(S) 뒤 더블클릭 = 다시 고치기·모서리 끌어 크기.

## 4. 실시간 확대 (Alt+2)

- Magnification API 돋보기 창(커서 모니터 전체 크기, 클릭 통과). `MagSetWindowFilterList(EXCLUDE)`로 자기 창 제외.
- **커서 따라가기 다듬기**: 원본 사각형 중심이 커서를 바로 따라가지 않고 프레임마다 `중심 += (커서 − 중심) × 0.35`, 커서가 중심 근처(원본 폭의 10%) 안이면 멈춤(작은 손떨림에 화면이 흔들리지 않게). 원본 사각형은 모니터 밖으로 나가지 않게 가둔다.
- 휠 = 1.25 · 1.5 · 2 · 2.5 · 3 · 4 · 6 · 8.
- **Alt+1 = 지금 확대된 장면 그대로 멈추고 판서**: 지금 원본 사각형과 배율을 판서 모드의 초기 확대 상태로 넘긴다(정지 이미지는 모니터 전체를 새로 찍고, 판서 쪽 확대 변환을 같은 값으로 시작).

## 5. 녹화 (F3)

- F1과 같은 범위 고르기(모니터 전체는 클릭 한 번, 창을 고르면 **그 창 녹화** — 창이 움직여도 따라감).
- 시작 전 확인: 저장 폴더 남은 공간 ≥ 예상 10분 용량(1080p30 기준 분당 약 20MB [추정 — 첫 측정으로 교체]) — 모자라면 "남은 공간이 n분 정도예요" 말풍선 후 그대로 시작.
- 안내 UI(알약·점선 테두리·말풍선)는 `WDA_EXCLUDEFROMCAPTURE`, 판서 오버레이는 녹화에 포함.
- 잠금·절전·모니터 해제 → 자동 중지·저장(파일 손상 방지). 시작 1초 안의 중지도 정상 파일(ZoomIt의 트랜스코더 예외 처리 참고).
- 저장 이름은 캡처와 같은 규칙, 확장자 `.mp4`.

## 6. 단축키

### 6.1 등록 트랜잭션

```
[적용] → 바뀐 줄마다: 새 키 RegisterHotKey(MOD_NOREPEAT) 시도
   성공 → 옛 키 해제 → "등록됨"
   실패 → 옛 키 유지(다시 등록) → 그 줄 빨간 표시 + 원인 찾기
```

### 6.2 원인 찾기와 추천

1. 이 앱 안에서 겹침 → "‘창 캡처’와 겹쳐요".
2. 알려진 앱이 실행 중인지(프로세스 이름만): Snipaste(F1·F3·Ctrl+F1·Shift+F3·Ctrl+F3), 아이캔 줌잇(Ctrl+1~4), ZoomIt/PowerToys(Ctrl+1~8, Ctrl+Shift+4 등), Windows 캡처 도구(Win+Shift+S) → "Snipaste에서 먼저 쓰고 있어요".
   - **등록이 성공해도 확인한다**: PowerToys는 전역 키를 저수준 훅으로 받아 `RegisterHotKey`로는 겹침이 안 보인다(이 PC에서 PowerToys 항상 위 Alt+Shift+D가 켜져 있는데 같은 키 등록이 성공함, 2026-11-25). PowerToys 프로세스가 있으면 모듈 설정 파일(읽기만)의 단축키와 비교해 "PowerToys ‘항상 위’가 먼저 가져가요".
3. 모르는 앱 → "다른 앱이 먼저 쓰고 있어요".
4. 추천 키 = 입력표 판정(`shortcuts::analyze`)에서 "비어 있음"인 조합(Ctrl+Alt+1~3, Alt+Shift+2·3, Ctrl+Shift+F1 …) 중 ① 지금 등록 가능 ② 이 앱 안에서 안 겹침 ③ 시스템 예약·한/영·Ctrl+Space·Caps Lock 아님 순으로 3개. **줄마다 첫 추천이 서로 다르게** 고른다(두 줄이 같은 추천을 눌러 다시 겹치지 않게).
5. 겹친 원인이 **모두 대체 앱 하나**(예: Snipaste가 F1 계열 4개)면 키를 바꾸라고 하기 전에 "그 앱 자동 시작 끄는 법"을 먼저 보여 준다 — screen-ink가 그 앱을 대신하므로 확정본 키를 그대로 쓰는 편이 낫다.
6. 글자 하나·Shift+글자는 전역 키로 받지 않는다(타자를 막음).
7. F키를 전역으로 쓰면 첫 등록 때 한 번 "다른 앱의 F1 도움말·F2 이름 바꾸기·F3 찾기가 막혀요" 안내.

### 6.3 두 번 누르기

같은 키 두 번(400 ms 안): F2 = 활성 창 캡처. 다른 키는 1차에서 두 번 누르기 의미 없음(오작동 방지).

## 9. 창 항상 위 고정 (Windows만, P1 — PRD R-TOP)

PowerToys 항상 위(`src/modules/alwaysontop`, MIT)의 흐름에 판단 몇 가지를 더한다.

```
Alt+Shift+D → 대상 = GetForegroundWindow의 최상위 창
  건너뛰기: 바탕 화면·작업 표시줄·시작 메뉴 · screen-ink 창 · 숨김·최소화 · cloaked(다른 가상 데스크톱)
            → 말풍선으로 이유 한 줄
  screen-ink 표시가 있음        → 풀기(HWND_NOTOPMOST + RemoveProp) · 테두리 지우기
  PowerToys 표시가 있음          → 건드리지 않음 · "PowerToys가 고정한 창이에요"
  표시 없이 원래 맨 위(WS_EX_TOPMOST) → 건드리지 않음 · "이 창은 원래 맨 위에 있어요"
  그 밖                          → 고정(HWND_TOPMOST + SetProp) · 테두리 · 말풍선
  SetWindowPos 실패(관리자 권한 창, UIPI) → "관리자 권한 창이라 고정할 수 없어요"
```

| 경우 | 스마트 처리 |
|---|---|
| 고정한 창을 끌기·최대화·최소화·숨김 | 테두리가 따라가거나 숨음(`SetWinEventHook`, `WINEVENT_OUTOFCONTEXT` — 다른 앱에 주입 없음) |
| 고정한 창이 닫힘 | 목록에서 빼고 테두리 지우기(말풍선 없음) |
| F1·F2 캡처·F3 녹화 | 테두리는 `WDA_EXCLUDEFROMCAPTURE`라 결과에 안 찍힘. 고정한 창도 범위 인식 후보에 그대로 나옴 |
| 판서·칠판·실시간 확대 진입 | 오버레이가 고정한 창보다 위(오버레이를 띄울 때 맨 위로 다시 올림) |
| 전체 화면 D3D 게임 | 키를 무시(PowerToys 기본) |
| 앱 끝내기 | 모두 풀기 |
| 비정상 종료 뒤 다음 시작 | `EnumWindows`로 screen-ink 표시가 남은 창을 찾아 풀기 |
| 모니터 변경·DPI 변경 | 테두리 다시 계산(DWM 확장 프레임) |
