# Windows 캡처·판서·실시간 확대 200회 반복 측정 · 2026-11-27

**세 모드 모두 진입·종료 200회를 완료했고, 세 모드 모두 7.4 기준에 미달했다.** 아래 값은 앱과 WebView2 자식 11개를 합친 시작·종료 중앙값이다. 앱 자체의 GDI 개수는 세 모드 모두 20회부터 200회까지 일정했다. 프레임이 한 장씩 누적되거나 매회 같은 핸들이 남는 누수는 확인되지 않았다.

|---|---:|---:|---|
| 캡처 → Esc | 831.1 → 1,532.3 MiB (+84.4%) | 5,328 → 5,712 (+384) | 미달 |

W7의 캡처 종료 중앙값은 1,385.2MiB(+34.2%)였다. 이번에도 시작 때보다 높은 작업 집합이 남았다. W7은 다른 작업을 수행했던 프로세스에서 두 화면으로 커서를 옮겨 측정했고, 이번에는 주 4K 화면에 커서를 둔 채 한 모드만 반복했다. 두 수치의 차이에는 시작 상태와 입력 조건의 차이도 포함된다.

## 측정 조건

- 기준 커밋 `0fac24b`. `npm ci`와 `npm run app:build -- --no-bundle`로 만든 릴리스 실행 파일을 `C:\agents\runs\W8-soak\app\`에 복사했다. 사본의 SHA-256은 `7F705C4C29B5958C442B1E6382DBD2F2505015B497224C9B3E5D690C76342E9A`다. `C:\agents\status.ps1`에서 W8만 실행 중임을 확인했다.
- Windows 11 Pro 빌드 26200, Ryzen 5 7500F, GeForce RTX 4060, WebView2 158.0.4370.33에서 측정했다. 주 화면은 물리 좌표 (0, 0), 3840×2160·200%다. 오른쪽 화면은 (3840, 0), 1920×1080·100%다. 모니터별 DPI를 적용한 스레드에서 192·96 DPI를 확인했다. 두 화면에 시험용 정지 배경을 띄우고 커서를 주 화면 (640, 420)에 뒀다. 캡처는 두 화면을, 판서와 확대는 주 4K 화면을 사용했다.
- 모드마다 새 앱 프로세스를 띄우고 전용 WebView2 프로필을 사용했다. 임시 포터블 설정에서 캡처는 `Ctrl+Alt+F6`, 판서는 `Alt+1`, 확대는 `Alt+2`로 열었다. 전역 단축키 16개가 모두 등록됐다. 캡처와 판서는 준비 로그가 나온 뒤 주 화면의 오버레이에 포커스를 맞추고 `Esc`를 눌러 두 오버레이 창이 모두 숨었는지 확인했다. 확대는 매회 진입·종료 로그를 짝지었다. 주석·저장·핀·모드 전환은 반복 동작에 포함하지 않았다.
- 준비 후 8초 이상 지난 시점에서 시작 표본 3개를 읽었다. 매 20번째 종료 후 약 2초부터 표본 1개를 읽고, 200회 때는 표본 2개를 더 읽었다. 그 뒤 32초를 추가로 기다려 유휴 표본을 읽었다. 별도 표기가 없는 회차 행은 n=1로 중앙값·p95·최대가 모두 표시값과 같다. p95는 올림 순위법을 사용했다.
- 앱 사본의 PID에서 시작해 부모 PID로 이어진 `msedgewebview2.exe`만 합산했다. `Get-Process`의 작업 집합(`WorkingSet64`)·전용 바이트(`PrivateMemorySize64`)·핸들 수(`HandleCount`)를 사용했다. 앱의 GDI·USER 개체는 `GetGuiResources`의 현재 개수다. 메모리는 MiB(1,048,576바이트), 핸들과 개체는 개 단위다. **합산 작업 집합에는 프로세스 사이의 공유 페이지가 중복될 수 있다.**
- 7.4의 판정은 W7과 같이 앱과 자식의 합산 작업 집합·핸들에 시작·종료 중앙값을 적용했다. 기준은 메모리 증가 5% 미만, 핸들 증가 0개다. [7.4 목표](../prd/07-plan.md) · [W7 측정 조건과 결과](2026-11-27-windows.md)

## 증가분이 남은 위치

- **캡처.** 0→20회에 합산 작업 집합이 657.2MiB 늘었고, 20→200회에는 44.0MiB 늘었다. WebView2 렌더러 6개의 작업 집합 합계는 20회 1,042.8MiB, 100회 1,084.8MiB, 200회 1,084.4MiB였다. 앱의 전용 메모리는 20~200회에 91.4~92.6MiB였다. 160회에 합산 작업 집합이 1,621.6MiB까지 올랐다가 200회에 1,532.3MiB로 돌아왔다. 높은 상주량을 더 조사할 위치는 두 오버레이 렌더러의 BMP 해석·오프스크린 캔버스·합성 표면이다. 프로세스 지표로 이 셋의 몫을 각각 산출할 수는 없다.
- **판서.** 20회에 WebView2 GPU 프로세스 전용 메모리가 631.2MiB였고, 200회에 600.1MiB, 추가 유휴 뒤 341.2MiB였다. 같은 구간 앱 전용 메모리의 회귀 기울기는 100회당 +0.5MiB였다. 4K 원본이 매회 한 장씩 남는다면 100회당 약 3,164MiB가 늘어야 한다. 아래 해제 계측에서도 정상 종료 때마다 원본과 비트맵이 반환됐다.
- **실시간 확대.** 앱 전용 메모리는 시작 54.8MiB에서 20회 121.2MiB로 올랐고, 200회에도 121.6MiB였다. 20~200회 앱 핸들은 769→765개, GDI는 66→66개였다. 200회 모두 돋보기 숨김·합성 완료 로그와 1틱 이상 진행된 확대의 종료 로그가 짝을 이뤘다. 첫 사용 뒤 유지되는 네이티브 돋보기 자원이 초기 단차의 후보다.
- **해석 범위.** 표의 기울기에는 초반 수십 회의 증가도 들어 있다. 캡처 합산 핸들은 100회 5,731개에서 200회 5,713개로 줄었다. 판서와 확대에서도 앱 핸들의 기울기는 음수였다. 양의 합산 기울기만으로 해제되지 않은 Windows 핸들·창·D3D 개체를 특정할 수 없다. 이번 600회와 아래 수명 검사에서 매회 누적되는 소유권 누수는 찾지 못해 제품 코드는 수정하지 않았다.

### 아무 모드도 열지 않은 대조군

### 실제 세션에서 확인한 해제 시점

자원 측정을 끝낸 뒤 별도 프로필의 같은 릴리스 사본으로 다시 확인했다. 이때만 주 화면 웹뷰에 계측을 연결했다. 원본 주소를 확인할 때마다 새 쿼리 문자열을 사용했다. HTTP 404는 그 세션의 원본을 앱의 저장소에서 더 이상 꺼낼 수 없다는 뜻이다.

| 대상 | 확인 결과 |
|---|---|
| 일반 캡처 원본 | 5회 × 모니터 2대. 진입 중 원본 주소 10개가 모두 HTTP 200, Esc 직후 같은 세션·모니터의 주소 10개가 모두 404였다. |
| 4K 판서 원본 | 20회 모두 진입 중 원본 주소는 200, 종료 직후에는 404였다. 실제 웹뷰에서 공유 버퍼 수신 20건과 `releaseBuffer` 성공 20건을 대조했다. 반환한 총량은 663,552,000바이트였고 같은 버퍼를 두 번 반환한 경우는 0건이었다. 추적한 4K 비트맵 20개도 각 세션 종료 때 20개 모두 `close()`를 마쳤다. |
| 5초 되살리기 | 시험용 확정 범위에 주석 1건을 서비스에 전달하고 취소했다. 취소 후 0.24초·4.63초에는 원본이 200, 5.40초에는 404였다(n=1). 5초 경계에서의 복원 거절과 저장소 해제 요청은 별도 단위 시험으로 검사했다. |
| 핀과 최근 5장 | 시험 범위 6개를 차례로 고정하고 하나씩 닫았다. 매번 핀 창이 파괴되고 앱의 핀 수가 0으로 돌아갔다. 해당 핀의 원본 주소도 200에서 404로 바뀌었다. 6번째 뒤 최근 목록에는 6·5·4·3·2번만 남았다. 1번 미리보기는 404, 2번은 200이었다. 30분 만료는 모의 시계로 검사했다. |

## 검증과 남은 확인

- 릴리스 빌드 성공. 본 측정 로그에서 각 모드의 진입·종료 200쌍, 모드별 표본 16개, 각 표본의 WebView2 자식 11개를 대조했다. 판서 공유 원본 200건의 세션 번호는 1~200으로 연속이었다.
- Rust 서비스·어댑터 단위 시험 35개, 인계·핀·확대 통합 시험 32개, 공유 버퍼 취소 경로의 자바스크립트 시험 1개가 통과했다. 전체 워크스페이스 시험, 최근 목록 만료까지 실제 30분 대기, 학교 PC·맥 측정은 미실행이다.
- 시험 앱·창은 종료했고 포터블 단축키 설정은 원복했다. 시작과 종료 때 사용자 설정 파일은 없었다. 화면 스크린샷은 저장하지 않았다. 측정용 WebView2 프로필 5개는 작업 노드의 자동 승인 검토에서 폴더 삭제가 차단되어 실행 폴더에 남았다.
